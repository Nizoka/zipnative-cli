# zipnative-cli v1.1.0

<!-- GitHub Release title: v1.1.0 — zipnative 1.1.0 parity and hardening -->

_Released 2026-10-18_

Built on **zipnative 1.1.0** (`^1.0.0` → `^1.1.0`, still the only runtime dependency). This
release has two parts. The first is **engine parity**: the CLI bridges all 106 engine exports
and exposes, as flags, the 1.1.0 capabilities that complete existing commands. The second is
**hardening** to the level of pkinative-cli and zipnative 1.1.0, across the runtime, the release
pipeline and the repository.

Three hardening items narrow what 1.0.0 accepted. They ship as **security fixes in a minor
release**, with the migration below. Everything else is additive: the `--json` envelopes, the 13
`E_*` codes, the exit codes and the `ZIP_*` mapping are unchanged. The 37 archives of the 1.0.0
conformance corpus are byte-identical when 1.1.0 writes them. Offline in every mode. Node.js ≥ 22.

## Highlights

- **Streamed Zip64** — a streamed entry may now exceed 4 GiB:
  ```bash
  tar -cf - build/ | zipnative create --stdin-name build.tar --zip64 -o build.zip
  ```
- **Legacy names, decoded** — `--name-encoding shift_jis` (or `gbk`, `windows-1252`, any WHATWG
  label) on `list`, `inspect`, `cat`, `extract` and `stream`. The engine decodes **before** it
  sanitises, so extraction guards still apply.
- **A deadline and a progress feed for agents** — `--timeout 30s` stops a run with `E_LIMIT`
  (`detail.limit: "timeout"`) and removes the partial output. `--progress` streams the engine's
  progress on stderr, as NDJSON `{"type":"progress",…}` under `--json`.
- **The engine's own determinism verdict** — `inspect` reports `canonicalForm` and
  `offenders: [{ name, concern }]` from `analyzeDeterminism()`; `--check canonical-form` gates
  on it.
- **Richer rows** — `--long` adds `timestamps` (UT / NTFS / DOS, with `source`) and `unixIds`.
- **A configuration file can no longer weaken a run** — `.zipnativerc.json` is presentation
  only.

## Security and behaviour changes

Each item has an ADR in [docs/adr/](../docs/adr/README.md) and a migration line in
[CHANGELOG.md](../CHANGELOG.md#security).

- **fix(security): the configuration file is presentation only** (ADR 0001). In 1.0.0, a
  `.zipnativerc.json` planted in a parent directory could disable the limits, or turn on
  `--overwrite`, `--skip-unsafe` or `--allow-symlinks`, for every command run below it. Only
  `codec` was refused. The file may now set `format`, `fields`, `json`, `pretty`, `quiet`,
  `no-color`, `progress`, `strict`, `long` and `summary`. Any other key is `E_USAGE` naming the
  file. The applying file is announced on stderr and in the envelope (`config: { path, applied }`).
- **fix(security): strict invocation** (ADR 0003). In 1.0.0 a misspelt flag was ignored, so
  `--max-entires 10` ran with the default bound. Now an undeclared flag, a repeated switch or
  single-value flag, and surplus operands are `E_USAGE` (exit 2) before any input is read. This
  also applies to every `batch` task before the first one runs. `--constructor x` no longer
  crashes with `E_RUNTIME`.
- **fix(security): every bound is finite** (ADR 0002). `none` / `inf` are refused on `--max-*`,
  `--max-input-size` and `inflate --max-output`.
- **fix(security): one-descriptor reads, rename overwrites** (ADR 0005). `/dev/zero` as an input
  stops at `--max-input-size` with `E_LIMIT`. Under `--overwrite`, output is written to a
  temporary sibling and renamed into place, so a planted symlink is replaced, never followed.
- **fix(security): terminal-safe text** (ADR 0004). Control and bidi characters in entry names,
  comments and messages are escaped in text output. JSON stays exact.
- **fix: no data loss on an early error.** In 1.0.0, when the engine failed before the output
  was opened, `cat`, `inflate` and `create` could unlink a pre-existing file that the run had
  refused to overwrite.

No parser, writer or engine guard was loosened. `modify` still verifies every entry it
re-emits, and now also checks the local header of encrypted survivors.

## Added

- **feat(create):** `--zip64` with `--stream` / `--stdin-name` (`AddEntryOptions.zip64`).
- **feat(read):** `--name-encoding <label>` on `list`, `inspect`, `cat`, `extract`, `stream`.
- **feat(agent):** global `--timeout <duration>` (`E_LIMIT`, ADR 0006) and `--progress`
  (`ZIPNATIVE_PROGRESS=1`).
- **feat(inspect):** `canonicalExtras`, `canonicalVersionMadeBy`, `canonicalForm`, `offenders`;
  `--check canonical-form`.
- **feat(list):** `--long` rows with `timestamps` and `unixIds`.
- **feat(stream):** `--codec` methods decode through the codec's `createDecompressor()`. A codec
  without one is refused before the first byte, or skipped with `--skip-unsupported`.
- **feat(core):** all 106 zipnative exports bridged. `ZIP_TIMESTAMP_CLAMPED` is the 12th
  diagnostic. `maxEntryCompressedSize` is reported by `doctor` / `schema limits`, without a
  flag (ADR 0007).
- **feat(samples):** four new dual-shell demos — `create/08-zip64-stream`,
  `list/04-name-encoding` (with a foreign Shift_JIS archive), `inspect/04-canonical-form` and
  `agent/04-timeout-and-progress`. That makes 45 demos and 83 `run-all.js` jobs.

## Changed

- **chore(deps):** `zipnative` `^1.0.0` → `^1.1.0`. Inherited from the engine:
  - every inflate tier raises `ZIP_DEFLATE_CORRUPT` / `ZIP_DEFLATE_TRUNCATED`;
  - `verifyEntry().skipped` names why an entry was not verified;
  - out-of-range DOS dates are clamped and reported;
  - an AES entry is named (`detail.feature: "aes"`).
- **refactor(core):** the CLI-side compensations for those engine gaps are removed: the zlib
  error translation, the skip re-derivation, and the Unix-mode encoder (masked to `0o777`, so no
  setuid / setgid / sticky bit is ever written).
- **refactor(core):** `dosTimeMode` is deliberately not adopted (ADR 0008). The CLI's DOS-date
  convention is per entry: explicit dates store UTC fields; `now` / `--mtime` store local time.
- **fix(cli):** text errors read `error E_X (ZIP_Y): message`. Exits wait for stdout / stderr
  to drain. `--json` is honoured for argv-parse refusals.
- **ci(supply-chain):** five-job release, `guard` → `build` → `publish` → `attest` →
  `consumer`
  (ADR 0009):
  - the tag must equal `v<version>`;
  - `build` holds no OIDC token and no cache;
  - `publish` runs behind the `npm-publish` environment, with an npm client pinned by SHA-512;
  - `attest` fetches the tarball back from the registry, and writes and attests the CycloneDX
    and SPDX SBOMs (`npm sbom`); it runs no registry code next to its signing identity;
  - `consumer`, read-only, installs the published version and runs `npm audit signatures`.
- **ci(supply-chain):** `scripts/gate.mjs` is the single definition of green. It includes a
  reproducible-build check, a bundle probe, a frozen tarball file list (10 files) and an install
  smoke test.
- **ci(supply-chain):** every job runs harden-runner first, `npm ci --ignore-scripts`,
  read-only top-level permissions and SHA-pinned actions.
- **ci(supply-chain):** new workflows and checks: zizmor, actionlint, `reuse lint`,
  OSV-Scanner, dependency review, a Node 26 advisory run and sample regression.
- **ci(supply-chain):** rulesets, `SECURITY-INSIGHTS.yml` and `security.txt` are kept as code.
- **feat(batch):** directory mode declares every `create` flag it forwards (`--include`,
  `--exclude`, `--stream`, `--parallel`, …). A manifest `comment-file` resolves against the
  manifest directory, like the other path flags.
- **chore(quality):** stricter TypeScript (`exactOptionalPropertyTypes`, …) and ESLint
  (`no-console`, no `zipnative` import outside the bridge). Coverage thresholds ratcheted to
  95 / 91 / 97 / 96.
- **test(conformance):** veraZIP re-ported from zipnative 1.1.0, adding the
  `WF/DESCRIPTOR-WIDTH` check. The corpus is now 39 archives, adding `--stream --zip64` and a
  clamped date.

## Fixed

- **fix(io):** the early-error unlink of a pre-existing output (above).
- **fix(io):** large entries no longer print `MaxListenersExceededWarning` on stderr (a 1.0.0
  listener leak in the file writer).
- **fix(cli):** a run never ends with exit 0 while an engine call is still pending; the files
  being written are removed.
- **fix(glob):** an out-of-order character class (`'[h-%]'`) is a usage error, not
  `E_RUNTIME`. The new seeded fuzz suite found it (ADR 0010).
- **fix(args):** prototype names (`--constructor`, `--__proto__`) are `E_USAGE`, not
  `E_RUNTIME`.
- **fix(hygiene):** a literal NUL in a source file is gone. A test now forbids raw control and
  bidi characters in tracked files.

## Upgrade

Drop-in for 1.0.0 except for the three narrowed inputs:

1. **A `.zipnativerc.json` with a non-presentation key now fails with `E_USAGE`.** Move
   `overwrite`, `skip-unsafe`, `allow-symlinks`, `max-*`, inputs and outputs to argv (or to a
   `batch` manifest task's `flags`).
2. **A flag the command does not declare now fails with `E_USAGE`.** Remove it — it was
   never honoured.
3. **`--max-* none` now fails with `E_USAGE`.** Pass an explicit size (`--max-total-size 64g`).

1.0.0 printed the bare error message (an `Error: ` prefix only for an unexpected runtime
error). Scripts that matched the start of the message should match `^error E_` or use `--json`.

Also narrowed, in the same spirit: a switch value outside `true|1|yes|on|false|0|no|off` is
`E_USAGE` (`--overwrite=flase` was read as ON), `batch` refuses a flag its mode ignores,
`extract --entry` naming no entry is `E_NOT_FOUND`, and `--workers` is bounded `0`–`64`.
